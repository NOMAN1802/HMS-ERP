## What was built

Staff can log in with a username and password, choose a hospital when they belong to several, stay logged in under the C-032 limits (60 minutes idle, 12 hours absolute), and log out. The session lives in a server-side table and travels in a host-only `HttpOnly`, `Secure`, `SameSite=Lax` cookie named `__Host-hms_session`. Every write needs an `X-CSRF-Token` header and an allow-listed `Origin`. Every route is protected by default: a session guard, a CSRF guard and a hospital guard run on all routes except those marked `@Public` or `@AllowWithoutTenant`.

Endpoints (API host, base path `/api/v1`):

| Method and path                 | Purpose                                           |
| ------------------------------- | ------------------------------------------------- |
| `POST /auth/login`              | Verify credentials, start a session (public)      |
| `GET /auth/session`             | Current session, hospitals and a fresh CSRF token |
| `POST /auth/session/membership` | Choose a hospital; issues a new session token     |
| `POST /auth/logout`             | Revoke the session and clear the cookie           |

## Decisions applied

1. **`auth_event` table for events before a hospital is known.** A failed login has no hospital, so it cannot go in the per-hospital `audit_event`. Once a hospital is bound, the login and logout are also written to that hospital's audit trail.
2. **CSRF token = HMAC-SHA256(`CSRF_SECRET`, session token)**, not a stored column. It can be re-issued with `GET /auth/session`, and rotating the secret invalidates all tokens.
3. **`audit_event` is not partitioned yet.** Monthly partitions arrive with retention (Q-053, T-PLT-02); Prisma does not model partitioned tables.
4. Wrong password, unknown user and disabled account all return the same `INVALID_CREDENTIALS`; unknown users still cost one argon2 check, so timing does not reveal valid usernames.
5. Choosing a hospital the user does not belong to returns `NOT_FOUND`, never revealing the hospital.
6. The session token is rotated on login and on hospital switch; the old token stops working immediately.
7. Idle expiry slides forward on activity (updated at most once a minute) but never past the 12-hour absolute limit.
8. ADR-003 evidence item 5 is now met: `hms_app` cannot `UPDATE` `audit_event` or `auth_event`.

## Security review (independent reviewer, before merge)

A separate security reviewer read the whole branch. Everything below was fixed test-first in this PR (failing tests committed first, then the fixes):

| Finding                                                                                                          | Fix                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| A disabled account or a suspended/revoked membership did not end an open session (FR-ACC-010)                    | `resolveSession` now checks the account status and the membership on every request                                           |
| Switching hospital reset the 12-hour absolute limit                                                              | The new session keeps the old absolute expiry                                                                                |
| Login skipped the Origin check, so another `*.bytespate.com` site could log a victim into the attacker's account | The Origin allow-list now applies to every write, including login                                                            |
| A sibling subdomain could shadow the cookie (cookie tossing)                                                     | Cookie renamed `__Host-hms_session`                                                                                          |
| Lock and disabled state were revealed without the password, and disabled accounts answered faster                | The password is verified first; status is only revealed after a correct password                                             |
| A password typed into the username field was stored in the append-only `auth_event`                              | Only username-shaped values are stored                                                                                       |
| A temporary lock with no end time let the user in                                                                | Treated as locked                                                                                                            |
| Error filter: details could override status/code, framework messages were echoed, 500s were not logged           | Fixed titles, details first, 400/413 mapped, unexpected errors logged server-side                                            |
| Client `X-Request-Id` stored without validation                                                                  | Only `[A-Za-z0-9-]{1,64}` is accepted                                                                                        |
| Membership policy let a user move a row between hospitals; tenant names visible for inactive memberships         | Migration `20261014110000_harden_identity_policies`: read-own policy is SELECT-only, tenant name only for ACTIVE memberships |

Deferred on purpose (not exploitable through the current code, tracked here):

| Item                                                                                                                      | Plan                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `user_account`, `user_session` and `auth_event` have no RLS and `hms_app` can UPDATE them (identity is global)            | Column-level grants once password change/reset exists (T-ACC-03 or later)                                     |
| `user_session` does not enforce in the database that its membership belongs to the same user                              | Enforced in code on every request (`isMembershipActive`); add a composite key when the schema is next changed |
| Argon2 has no concurrency cap, so many parallel logins use CPU and memory                                                 | Rate limiting and a cap in T-ACC-03                                                                           |
| Each request now costs two extra small queries (account, membership)                                                      | Add a short-lived cache with explicit invalidation if load tests show a need (M)                              |
| Confirm on staging that `@prisma/adapter-pg` through the Supabase pooler (port 6543) creates no named prepared statements | Staging check                                                                                                 |

## How to debug

- **Cookie not sent by the browser:** the cookie is named `__Host-hms_session` and is `Secure`, so it needs HTTPS (browsers refuse the `__Host-` prefix over plain http, except on `localhost`). `http://localhost` is the only plain-http exception browsers allow.
- **403 `CSRF_TOKEN_INVALID`:** check that the `X-CSRF-Token` header matches the value from the last login or `GET /auth/session`, and that the request `Origin` is listed in `CORS_ORIGINS`.
- **403 `TENANT_NOT_SELECTED`:** the user has several hospitals; call `POST /auth/session/membership` first.
- **401 right after login:** check the server clock and `SESSION_IDLE_TIMEOUT_MIN` / `SESSION_ABSOLUTE_TIMEOUT_H`.
- **API refuses to start:** `CSRF_SECRET` must be at least 32 characters and `DATABASE_URL` must be set.
- **Why a login failed:** query `hms.auth_event` (`action`, `outcome`, `reason`) for the username or user ID. Reasons: `UNKNOWN_USER`, `BAD_PASSWORD`, `ACCOUNT_LOCKED`, `NO_ACTIVE_MEMBERSHIP`.
- **After editing `schema.prisma`:** run `pnpm db:migrate`; it now also regenerates the Prisma client (the typecheck and tests fail with `undefined` models if the client is stale).
- **Local database tests fail with "Can't reach database server":** start the containers with `pnpm services:up`.
