# T-UI-01 S1: design tokens, themes and fonts

- **Date:** 2026-10-15
- **Commit:** this commit (red test fa3db05, tokens 2ebdb51)
- **Implements:** task T-UI-01 (slice S1), NFR-ACC-001, decisions C-055, C-056, ADR-022 sections 2 to 5, 9 (rule 5), 13 and 14

## What was built

The shared design tokens now exist in `packages/ui` and the web app uses them. A developer imports `@hms/ui/styles.css` once and gets the semantic colors (as Tailwind utilities such as `bg-primary`, `text-text-muted`, `bg-status-done-bg`), the three font stacks, the radius scale and the base styles. Light is the default theme; a dark theme exists but switches on only with `data-theme="dark"`. Tailwind's default palette is removed, so no raw color can be used by accident. A contrast test fails the build if any token pair drops below WCAG AA.

## Decisions applied

- Token names follow ADR-022 section 2. Status tokens are named `--color-status-<meaning>-bg` and `-text` (not `--status-*`) so Tailwind generates utilities from one namespace.
- `--color-border-strong` is mist-500 `#67787c`: 4.61:1 on white and 4.45:1 on the page background (needs 3:1). This closes that ADR-022 open item.
- The dark theme uses mist-950 and mist-900 surfaces, teal-400 primary with teal-950 labels, cyan-400 accent and 950/200 status pairs. Every pair was computed before writing and passes (text 16.7 to 19:1, primary 9.3:1, status text 10.3 to 13.3:1).
- Tailwind's default colors, fonts and radii are removed with `initial`, so only tokens generate utilities.
- Fonts are npm packages (Fontsource, exact versions, lockfile) so no binaries are committed and nothing loads from a CDN. Each family has unicode-range subsets, so only the scripts a page uses are downloaded.
- The test reads the CSS as text and parses `--name: #hex;` lines, so it runs without a browser.

## Known limitations

- No components yet: S2 (guardrail lint rules), S3 (hooks) and S4 (primitives) follow.
- Print tokens (monochrome) are deferred to the print templates task; only the screen themes exist.
- The type scale (heading sizes, compact worklist size) is not defined yet; only body text (16 px, line height 1.6) is set.
- Dark has no visual review, and nothing exposes it (no toggle).
- Tiro Bangla rendering at body size, Bengali digit alignment and Geist tabular figures are still to be checked on real 1366x768 monitors.
- The `@source` line in `apps/web/app/globals.css` scans `packages/ui/src` for class names; nothing there uses classes yet.
- `packages/i18n` still exports `defaultLocale = 'en'`, while the user preference default in the schema is `bn-BD` (Bangla first). That belongs to T-I18N-01.

## How to debug

- A color looks wrong: find the token in `theme-light.css` (or `theme-dark.css`), never a literal; check `data-theme` on `<html>`.
- A utility such as `bg-red-500` does nothing: the default palette is removed on purpose; use a semantic token.
- Bengali text shows in a fallback font: confirm the `Noto Sans Bengali Variable` font loaded (Network tab, a `bengali` subset woff2) and that the family name in `tokens.css` matches the name in the Fontsource CSS.
- The contrast test fails: it names the pair; fix the token value, then re-run `pnpm --filter @hms/ui test`.
